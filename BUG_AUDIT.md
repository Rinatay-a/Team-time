# Аудит дефектов версии 1.0

| Дефект | Риск | Исправление 2.0 |
|---|---|---|
| Захват pointer отдельной ячейкой + ожидание `pointerenter` соседей | Drag срывался: после capture события адресуются захватившему элементу | Capture перенесён на сетку; `pointermove` обрабатывается централизованно, слот определяется через `elementFromPoint`, пройденные клетки хранятся в `Set` |
| Polling перезаписывал `name` и `selected` | Потеря несохранённой работы | Серверный снимок отделён от черновика; polling меняет только серверные данные/результаты |
| DELETE слотов, затем отдельный INSERT | Сбой вставки оставлял пустой ответ | Транзакционная SQL-функция заменяет ответ атомарно |
| Лимит 1000 | 42 дня × 15 минут не сохранялись полностью | Лимит рассчитывается по реальной сетке, максимум 5500; тестовый сценарий содержит 2352 слота |
| Вложенный PostgREST-ответ мог обрезаться лимитом 1000 строк | Неполное восстановление длинного ответа | SQL возвращает один агрегированный JSON-снимок |
| Валидация проверяла в основном строковый формат | Несуществующие даты, неверный шаг и DST-время | Проверяются календарная дата, HH:mm, границы, смещение от начала по шагу и обратное преобразование часового пояса |
| Нет контроля конкурентного редактирования | Тихая перезапись из второй вкладки | Сравнение `expected_updated_at`, код конфликта 409 и понятное сообщение |
| Потеря ответа API после успешного первого сохранения | Повтор мог создать дубликат участника | Браузер заранее сохраняет 256-битный pending-токен; повтор запроса идемпотентно находит ту же запись |
| UTC-дата в форме | Около полуночи могла подставиться не московская дата | `formatInTimeZone(..., 'Europe/Moscow')` |
| Демо автоматически включалось без env | Риск опубликовать несохраняющую демоверсию | Демо включается только явным `VITE_DEMO_MODE=true`; иначе экран ошибки конфигурации |
| Финализация недостаточно проверяла принадлежность сетке | Назначение неподходящего времени через API | Сервер проверяет тип, владельца, дату, границы, шаг и точную длительность |
| Публичные результаты | Риск раскрытия ФИО | При `organizer` чужие участники не возвращаются; прямой anon-доступ к таблицам по-прежнему запрещён |
| ICS не экранировал все специальные символы | Некорректный календарный файл | Экранируются обратные слеши, переносы, запятые и точки с запятой |
| CSV формировал неодинаковые колонки | Повреждённый экспорт | Колонки строятся единым `slotKeys()` |

## Остаточные риски
- Rate limit в таблице — базовая защита небольшого внутреннего сервиса, не полноценный WAF. Для публичного массового запуска нужен внешний лимит Supabase/Cloudflare.
- При открытых всем результатах ответ до 100 человек × 2352 слота может быть большим. Снимок не обрезается, но владельцу следует оставлять видимость «только организатор», если общие результаты не нужны.
- Юридическое соответствие и допустимость хранения ФИО в выбранном регионе Supabase должен отдельно проверить владелец проекта.
- Интеграционные проверки реального Supabase не выполнялись без тестового проекта и ключей.
